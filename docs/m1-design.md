# M1: 回路の詳しい設計（頂点ごとの語の案）

2026-10-10。回路 `hw/rtl/mc_core.v`・`hw/rtl/mc_lane.v` の仕様。規則は CPU 版 `sw/sa.c` と同じ
（design-draft.md の 2 章）。ここに書く段数・時刻は設計値で、正しさは xsim で CPU 版と全語照合して確かめる。

## 記号

| | |
|---|---|
| P | 1 本のパイプライン（レーン）に交互に流すレプリカの数。**2 のべき・12 以上**（下の先読みの時刻表が o = 11 まで使うため）。M1 は 16 |
| K | レーンの数。レプリカは R = K·P 個、レプリカ p = k·P + j（レーン k・スロット j） |
| W | 塗り分けの語の幅 = K·P。M1 は **W ≤ 64**（1 ビートに1語）。K = 1 なら 16 |
| D | 次数。合成時に固定（M1 は 4）。しきい値は n_same = 0, 1 の2つだけ使う（D = 3, 4 で足りる） |
| n | 頂点数。4 ≤ n ≤ 4096（頂点番号 12 bit） |

## 窓

全レプリカが同じ頂点 v を P クロックかけて処理する。この P クロックを**窓**と呼ぶ。
窓 w の頂点は v_w（順に回す）、試行番号 t = w（全レプリカで共通なので、t のカウンタは1つでよい）。
窓 w の中の時刻を o = 0 … P−1、スロット j = o のレプリカ j（各レーンの）が試行に入る。

### 塗り分けの置き場

| もの | 中身 | 置き場 |
|---|---|---|
| COL[v] | 頂点 v の色 × 全レプリカ（W bit。ビット p = レプリカ p） | BRAM（書き口 1・読み口 1・読み出し 2 クロック） |
| ADJ[v] | 隣 D 個の頂点番号（12 bit × 4） | BRAM（読み出し 2 クロック） |
| OWN[0], OWN[1] | 窓の頂点の語（交互に使う2本のレジスタ） | FF |
| NB[0..D−1] | 窓の頂点の隣の語 | FF |
| FWD[0..D−1] | 「隣 i が1つ前の窓の頂点」の印 | FF |

窓 w では OWN[w mod 2] がその窓の頂点の語。レプリカ j は自分のビットだけを読み書きする。
隣の色は窓の中で変わらない（自己ループが無く、変わるのは v_w だけ）ので、NB は窓の始めに揃っていればよい。

### 窓 w の中で、次の窓 w+1 の準備をする（時刻表）

BRAM は番地をレジスタに載せてから読むので、**時刻 o に番地を載せると o+3 で値が見える**（o+1 で読み、o+2 で rd1、o+3 で rd2）。
書き込みも o に載せると o+1 の終わりに書かれる。

| o | すること |
|---|---|
| 0 | ADJ の番地に v_{w+1} を載せる |
| 3 | 隣の番号を受け取る。FWD_next[i] = (隣 i == v_w) |
| 3 | **書き戻し**: COL[v_{w−1}] ← OWN[(w−1) mod 2] を載せる（o = 4 の終わりに書かれる） |
| 4〜7 | COL の番地に隣 0〜3 を載せる（o = 5〜8 で読む。書き戻しの後） |
| 8 | COL の番地に v_{w+1} を載せる |
| 7〜10 | NB_next[0..3] に受け取る |
| 11 | OWN_next に受け取る |
| P−1 | 窓の境目: NB ← NB_next、FWD ← FWD_next、OWN[(w+1) mod 2] ← OWN_next、t ← t+1、温度の段の切り替え |

正しさの理由:

- **隣が v_{w−1}**: o = 3 で書き戻してから o = 4 以降で読むので、BRAM から新しい値が出る
- **隣が v_w**（直前の窓。v_w の反転はまだ途中）: BRAM を使わず、窓 w+1 でレプリカ j が読むときに
  OWN[w mod 2] のビット j を直接使う（FWD）。レプリカ j の窓 w での反転は 時刻 wP + j + 4 から見え、
  窓 w+1 での読み出しは (w+1)P + j なので、P ≥ 4 なら間に合う
- **それより前の頂点**: もう書き戻してある
- **OWN[(w+1) mod 2] の上書き**（境目）: 中身は窓 w−1 のもので、o = 3 で書き戻し済み、FWD での読み出しも窓 w の中で終わっている
- **書き戻しの時刻**: レプリカ j の反転は S3（時刻 T+3）の終わりに OWN に書かれ、T+4 から見える。
  窓 w−1 の最後のレプリカ（T = wP − 1）の反転は wP + 3 = o 3 から見えるので、o = 3 で載せれば最新

最初の窓の前に「窓 −1」（試行を流さない窓。書き戻しなし、FWD なし）で窓 0 の準備をする。
最後の窓の後に「窓 WT」（試行を流さない窓）で最後の頂点を書き戻し、パイプラインを抜く。

## レーン（1 本のパイプライン）

レプリカ j が窓 w のスロットに入る時刻を T = wP + j とする。各段は「小さい演算ひとつ」。

| 段 | 時刻 | すること | レプリカごとの記憶（LUTRAM, P 語） |
|---|---|---|---|
| S0 | T | 隣のビット d 個（FWD なら OWN[前] から）と自分のビットを選ぶ。乱数の状態を読み、xorshift64 を1回進めて書き戻す | X（64 bit）: 読み・書きとも S0 |
| S1 | T+1 | n_same を数える。r < TH0、r < TH1 を並べて比べる（r = 新しい状態の上位 32 bit） | |
| S2 | T+2 | 受け入れ = (2·n_same ≥ D) or (n_same = 0 and r < TH0) or (n_same = 1 and r < TH1)。C を読み、受け入れなら C + ΔC | C（16 bit）: 読み S2・書き S3 |
| S3 | T+3 | C を書く。受け入れなら OWN[窓] のビット j を反転。best を読み、改善 = 受け入れ and C > best。到達 = 改善 and 未到達 and C ≥ C_target | best, hitv: 読み S3 |
| S4 | T+4 | 改善なら best ← C、best_t ← t。到達なら hit_t ← t、hitv ← 1 | best, best_t, hit_t, hitv: 書き S4 |

同じレプリカの次の試行は P クロック後なので、どの記憶も「書いてから次に読む」までが P − (書き段 − 読み段) ≥ P − 1 クロック空く。
TH と t は S0 で取り込んでパイプラインと一緒に運ぶ（窓の境目で変わるため）。

## ストリームの形（64 bit のビート）

入力（1 転送で1ジョブ。終わると次の見出しを待つ）:

| ビート | 中身 |
|---|---|
| 1 | [15:0] n、[23:16] d、[31:24] P、[47:32] S（温度の段数） |
| 1 | [15:0] C_target |
| n | ADJ: [11:0] 隣 0、[27:16] 隣 1、[43:32] 隣 2、[59:48] 隣 3 |
| n | COL: [W−1:0] 初期の塗り分け（ビット p = レプリカ p） |
| R | xorshift64 の種（レプリカ 0, 1, …） |
| R | [15:0] 初期のカット値 C0 |
| 2S | 段ごとに [31:0] 周回数、続いて [31:0] TH0・[63:32] TH1 |

出力:

| ビート | 中身 |
|---|---|
| 1 | [15:0] n、[23:16] d（入力の写し）、[31:24] P、[47:32] S、[63:48] 0x4D43 |
| 1 | 走った時間のサイクル数（窓 0 の始めから窓 WT の終わりまで。= (WT + 1)·P になるはず） |
| 1 | 窓の数 WT（= 1 レプリカあたりの試行数 = 総周回数 × n） |
| 3R | レプリカごとに [15:0] best・[31:16] 最後の C、best_t（48 bit。改善が無ければ全 1）、hit_t（48 bit。届かなければ全 1） |
| n | COL: 最後の塗り分け |

出力は 16 段の FIFO と出力レジスタを通す（背圧で落とさない。`load = !m_tvalid || m_tready`）。

## 検証（xsim、実測）

`python3 sw/mkvec.py --K <K>` で照合ベクタを作り、`hw/` で `vivado.sh sh 'sim/run.sh <K>'`。

| | K = 1（16 レプリカ） | K = 2（32 レプリカ） |
|---|---|---|
| 4 ジョブを続けて流す（循環グラフ n = 64、n = 64・256・100 のランダム 4 正則） | 出力 688 語すべて一致 | 880 語すべて一致 |
| 走ったサイクル数 | 設計値 (WT+1)·P と一致（15,376 / 40,976 / 122,896 / 8,016） | 同じ |

- 入力は tvalid をランダムに落とし、ときどき最大 40 クロック止める。出力は 1/3 の確率で tready を落とす
- 循環グラフ（v が v±1・v±2 とつながる）は、毎窓で FWD と「書き戻してから読む」の両方を通る
- 目標は「全員届く」「一部だけ届く」「目標 0 = 最初の改善で届く」を混ぜた
- **わざと壊して FAIL になることも確かめた**: FWD を切る（591/688 語が違う）、書き戻しを o = 5 に遅らせる（505）、
  受け取りを 1 クロック早める（676）

## 合成（K = 1、125 MHz、Mac mini で `build.tcl all 125 1 8`、実測）

| | 1 回目 | 直したあと |
|---|---|---|
| WNS | −0.095 ns（最悪経路: `stage` → `th_mem[stage + 1]` → `th1`、論理 6 段・配線 77%） | **+0.419 ns** |
| Slice LUT（DMA など込みの全体） | 12,769 | 6,163（11.6%） |
| FF | 31,982 | 7,561（7.1%） |
| BRAM タイル | 16.5 | 16.5 |

1 回目は温度の表（256 段 × 96 bit）が LUTRAM に載らず、2.5 万個の FF と大きな選択回路になっていた。
読み番地が2つ（`[0]` と `[stage + 1]`）あり、書き込みも本体の always の中にあったため。
表を別の always に移し、読み口を1つ（番地はレジスタで「次に切り替える段」）にしたら載った。xsim は直したあとも K = 1・2 とも全語一致。

## 実機（PYNQ-Z1、`host/mc.py`、実測）

照合の正解は、同じボードの CPU 版 `sw/sa` がその場で作る。

| ジョブ | 照合 | サイクル数（回路のカウンタ） | 時間 | 試行/秒 |
|---|---|---|---|---|
| n = 256、10 段 × 3 周回 | 307 語すべて一致 ×3 回 | 122,896（設計値と一致） | 0.983 ms | 1.25e8 |
| n = 1024、標準（100 段 × 10 周回）、16 レプリカ | 1,075 語すべて一致 ×3 回 | 16,384,016（設計値と一致） | 131.07 ms | **1.25e8** |

- 1 レーンで **1 クロック 1 試行**（125 MHz × 1）。CPU から測った DMA 込みの時間は 131.9 ms で、固定費は 1 ms 弱
- 同じ 16 レプリカの CPU 版（ボードの A9・1 スレッド・未最適化）は 1,817 ms（起動込み）。比べるのは最適化した CPU 版を作ってから（M4）
- M0 の M4（未最適化・10 スレッド）は 2.3e9 試行/秒。並ぶには K ≈ 18 レーンが要る（試算）。M1 の形は W = K·P ≤ 64（K ≤ 4）なので、
  K を増やすには塗り分けの語を複数ビートで送る形にする（M3）
