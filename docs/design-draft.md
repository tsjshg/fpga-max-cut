# 設計のたたき台: 焼きなまし Max-Cut エンジン（PYNQ-Z1）

2026-10-10 版。回路はまだ作っていない段階の案。3〜4 章の数字は試算。
M0（CPU 版）で決めたことは「8. 決めたこと」と docs/m0.md（こちらは実測）にまとめた。

## 1. 何を作るか

重みなし・次数 d 固定のグラフ G = (V, E)、|V| = n について、頂点を2色に塗り分け、
色が違う辺の数（カット値）をなるべく大きくする。

- 探索は**1頂点ずつ反転する焼きなまし**（Metropolis 法）
- **P 個の独立した探索（レプリカ）**を回路の中で同時に回す。初期解と乱数の種だけが違う
- 返すのは、レプリカごとの最良カット値、それが出たサイクル、最後の塗り分け
- 評価は「目標スコア C_target に届くまでの時間」とその分布、時間内の到達率と最良値

## 2. アルゴリズム（CPU 版と回路で同じもの）

頂点 v を反転したときのカット値の増分は、v と同じ色の隣の数 n_same、違う色の隣の数 n_opp を使って

    ΔC = n_same − n_opp      （n_same + n_opp = d）

で、−d, −d+2, …, +d の d+1 通りしか取らない。

1 回の試行（レプリカ p の試行 t。周回 k = t / n、頂点 v = t % n）。**M0 の CPU 版（`sw/sa.c`）がこの規則の正本**:

```
x ← xorshift64(x)、r = x >> 32           乱数は ΔC によらず毎試行1回進める
n_same = v と同じ色の隣の数、ΔC = 2·n_same − d
受け入れ = (ΔC ≥ 0) または (r < TH[段][n_same])
受け入れたら s[v] を反転、C += ΔC
  C > best（等しいときは更新しない）なら best = C、best_t = t
  C ≥ C_target にはじめてなったら hit_t = t（目標は初期値より大きくとるので、best の更新と同時に起きる）
```

- **しきい値の表は n_same（0〜d）で引く d+1 個**。`TH[n_same] = min(floor(exp(ΔC/T)·2^32), 2^32−1)`、
  ΔC ≥ 0 の欄は使わない（0xFFFFFFFF を入れておくが、r = 2^32−1 では r < TH が偽になるので
  「ΔC ≥ 0 なら受け入れ」の判定は回路でも別に持つ）。d が奇数でも同じ形で使える
- 表は `sw/make_sched.py` が**1回だけ**浮動小数で計算して整数のファイル（.sched）にし、
  CPU 版（Mac・ボード）と回路の全員がそれを読む。libm の差が入り込む余地をなくす
- 乱数はレプリカごとに独立な **xorshift64 (13, 7, 17)** の上位 32 bit。周期 2^64−1
- 種: 主種から始まる splitmix64 の列を 2^32 個ずつの区間に分け、レプリカ p は p 番目の区間を使う。
  最初の1個（0 なら次）が xorshift64 の種、続く ⌈n/64⌉ 個が初期の塗り分け。
  レプリカ数を変えてもレプリカ p の道筋は変わらない。回路には種と初期の塗り分けを CPU が渡す
- 記録するのは**試行番号 t**（サイクルではない）。CPU 版と照合でき、時間は t × P / f で決まる。
  回路のサイクルカウンタは総サイクル数（速さの確認）に使う
- 頂点の順番は**順に回す**（M0 で比較済み。ランダムに選ぶより TTS99 が約 4 倍良かった。docs/m0.md）
- 温度スケジュールは「(しきい値の表, その温度で回す周回数) の並び」として CPU が渡す

## 3. 回路の形

### 3.1 P 個のレプリカを1本のパイプラインに交互に流す

```
サイクル:   0    1    2   …  P−1   P    P+1  …
レプリカ:   0    1    2   …  P−1   0    1    …
頂点:       v    v    v   …  v     v+1  v+1  …
```

1本のパイプラインに、レプリカ 0, 1, …, P−1 の試行を1クロックずつ交互に入れる。

- **衝突が起きない**: 同じレプリカの次の試行は P クロック後。パイプラインの段数 L が P 以下なら、
  前の反転の書き戻しが必ず次の読み出しより先に終わる。前回いちばん苦労した
  「段数のずれ」を、形のうえで起こさないための選択でもある
- **隣接リストは P クロックに1回読めばよい**: 全レプリカが同じ順で頂点を回るので、
  P クロックのあいだ同じ v の隣接リストを使い回せる
- 速さは 1 本あたり 1 試行/クロック。125 MHz なら 1 本で 1.25 億試行/秒（試算）

### 3.2 メモリの置き方（n = 1024、d = 4、P = 16 の場合）

| もの | 大きさ | 置き場 | 読み書き |
|---|---|---|---|
| 塗り分け s[レプリカ][頂点] | 16 × 1024 = 16 Kbit | BRAM（16K × 1 の RAMB18） | 1 試行で d+1 個（隣 d 個と自分）読み、1 個書く |
| 隣接リスト adj[頂点] | 1024 × 4 × 10 bit = 40 Kbit | BRAM | P クロックに 1 回読む。全パイプラインで共有できる |
| 乱数の状態 | 16 × 64 bit | LUTRAM | 毎クロック 1 読み 1 書き |
| しきい値の表 | 温度数 × 2 × 32 bit | BRAM | 毎クロック 1 読み |
| カット値・最良値・そのサイクル | 16 × (13 + 13 + 48) bit | LUTRAM | 毎クロック 1 読み 1 書き |

**塗り分けを1クロックに d+1 個読む**のが、この設計でいちばん窮屈なところ。BRAM は1つにつき
読み書き口が2つしかない。案は2つ:

- **(a) d+1 個に複製する**: 同じ中身の BRAM を d+1 個持ち、反転のたびに全部へ書く。
  1 本あたり RAMB18 が d+1 個（d = 4 なら 5 個）。単純で、最初はこれでよい
- **(b) 色の付け方を工夫する**: グラフを彩色し、隣同士が別のバンクに入るように頂点を並べる。
  複製が要らなくなるが、前処理が要る。資源が足りなくなってから考える

### 3.3 パイプライン（1 本ぶん・案）

```
 段1  レプリカ番号 p、頂点 v を決める（カウンタ）
 段2  乱数の状態を読む（LUTRAM）／ 隣接リストは p = 0 のときだけ読む
 段3  s[p][隣 1..d] と s[p][v] を読む（BRAM・複製 d+1 個）
 段4  n_same を数える（d 個の XOR と小さな足し算）→ ΔC
 段5  しきい値を引く ／ 乱数を1つ進める
 段6  受け入れを決める（r < TH または ΔC ≥ 0）
 段7  s[p][v] に書く ／ C += ΔC ／ 最良なら最良とサイクルを更新 ／ 乱数の状態を書く
```

7 段前後なら P = 8 でも足りるが、BRAM の読み出しに登録段を足すと伸びるので **P = 16** を基本にする。
各段は「小さい演算ひとつ」に収める（前回の教訓: 1 クロックに重い処理を2つ並べない）。

### 3.4 何本並べられるか（試算）

1 本あたり BRAM は塗り分けの複製で RAMB18 が 4〜5 個、LUT は数百〜1,000 個程度と見ている。
XC7Z020 は RAMB18 が 280 個あるので、BRAM だけなら 40 本以上入るが、配線と LUT を考えると
**8〜16 本**が現実的な見込み。16 本 × 16 レプリカ = 256 レプリカ、125 MHz で 20 億試行/秒（試算）。
まず 1 本で正しく動かし、本数を増やしたときに**何が先に詰まるか**（BRAM・LUT・配線・タイミング）を測る。
それ自体が知りたいことの一つ。

## 4. ボードとのやりとり

fpga-mac のひな形と同じく、**AXI DMA のストリーム1本で流し込み、1本で返す**。制御レジスタは使わない。

入力（案）:

```
[見出し]      n, d, P, パイプライン本数, 温度の段数, 周回数の合計, C_target
[隣接リスト]  n 行 × d 個の頂点番号
[初期値]      レプリカごとの乱数の種、初期の塗り分け（またはその種）
[温度表]      段ごとに (しきい値 ⌊d/2⌋ 個, その段の周回数)
```

出力（案）:

```
レプリカごとに: 最良カット値、それが出た試行番号、C_target に届いた試行番号（届かなければ全 1）、最後のカット値
全体で:         総サイクル数（試行番号 × P / f と一致するかで速さを確かめる）
最後の塗り分け（検証用。全レプリカぶん）
```

**最良の塗り分けそのものは回路に持たない**。最良が更新されるたびに n bit を写すのは重い。
CPU 版がビット単位で同じ道筋をたどるので、最良が出たサイクルが分かれば CPU で再現できる。

## 5. 検証の順番

1. **CPU 版（C）を先に書く**。これが正解。整数の乱数としきい値の表を使い、回路と同じ規則で動く。
   Mac とボードの両方で焼き、同じ結果になることを確かめる
2. **問題の生成器**（Python）: ランダム正則グラフ（自己ループと多重辺なし）、G-set の読み込み
3. **1 本・P = 16 を xsim で**: CPU 版が書き出した期待値（各レプリカの最良値・そのサイクル・
   最後の塗り分け）と全部一致させる。入力の途切れと背圧をかける
4. **実機で 1 本**: 同じ照合を実機で。ここで初めて速さを見る
5. **本数を増やす**: 1 → 2 → 4 → 8 → 16 本。資源・WNS・速さを表にする
6. **到達時間の測定**: ランダム正則グラフと G-set で、C_target までの時間の分布を取る

| M4 の Mac（全コア） | 同上、全コアのスレッド | **負ける可能性が十分ある** |

## 8. 決めたこと（2026-10-10）

| 項目 | 決定 | 根拠 |
|---|---|---|
| 頂点の順番 | 順に回す | M0 で TTS99 がランダム選択の約 1/4（docs/m0.md・実測） |
| d と n | d = 4、n = 1024 で始める（デバッグ用に n = 64・256）。CPU 版は d・n とも可変。**回路は n ≤ 4096** で作る（G48〜G50 が n = 3000） | G48〜G50 と同じ次数。ΔC = 0 の分岐も通る |
| 乱数 | xorshift64・上位 32 bit・毎試行1回進める。種は splitmix64 | M0 で splitmix64 に替えても TTS99 が誤差内で同じ（実測） |
| 評価 | **TTS99** で比べる。「試行回数の分布（アルゴリズムの性質・CPU で測る）」と「試行/秒（実装の速さ）」に分けて測る | 同じアルゴリズムなら試行回数は CPU と回路で同じなので、速さの比は試行/秒の比に帰着する |
| C_target | 長い CPU 探索で得た最良値の 99%・99.5%・100%（その割合以上で最小の偶数。d が偶数ならカット値は偶数） | n = 1024 の乱数種 1 のグラフは 1774（最良既知・最適の証明は無い） |
| 温度スケジュール | 幾何級数。標準は T0 = 0.8、T1 = 0.2、100 段 × 10 周回（τ = 1000 周回） | M0 の格子探索（docs/m0.md） |
| FCLK | 125 MHz から | 前回の AXI DMA の経験 |
| 塗り分けの置き方 | **M1 の前に決める**。候補は (a) d+1 個の複製、(c) 頂点ごとに P bit の語（下記） | |
| G-set | 使うのは G48〜G50（トーラス・次数 4・重みなし）。最良既知値は出典を確かめて記録する。最良既知値を「最適値」と呼ばない | G-set の大半は次数がそろわず、G57 以降のトーラスは ±1 の重み |

### 塗り分けの置き方の案 (c): 頂点ごとに P bit の語

全レプリカが同じ頂点 v を P クロックかけて処理するあいだ、隣 u の色は変わらない
（自己ループが無く、変わるのは v だけ）。そこで塗り分けを `s[頂点]` = P bit（全レプリカぶん）の語で持つ:

- 窓の始めに隣の語を d 個読む。v 自身の語はレジスタに持ち、各レプリカが自分のビットを反転、窓の終わりに1回書き戻す
- BRAM の読み書きは P クロックに d+2 回。**ポート1つで足り、複製が要らない**
- K 本のパイプラインは幅 K·P bit の1つのメモリを共有できる。律速は BRAM から乱数・比較器・カット値の LUT に移る
- 次の窓の隣に今の v が入っているときは、レジスタから回す（書き戻し前の値を読まない）

M0 の実測で、未最適化の CPU 版が M4 の 10 スレッドで 2.3e9 試行/秒出た（3.4 の FPGA の試算 2e9 を既に超える）。
本数を大きく増やせる (c) を有力とみている。
