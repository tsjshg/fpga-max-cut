Solving Max-Cut on an FPGA

Colour the vertices of a graph with two colours so that as many edges as possible join different colours. The problem is easy to state and very hard to solve exactly. This page explains what Max-Cut is and what kinds of methods exist for it. It then covers the key points of the method chosen here, simulated annealing, and how it was built as a hand-written circuit on the FPGA of a PYNQ-Z1.

Numbers are measured unless stated otherwise. The implementation and the measurement notes are in the GitHub repository.

01What Max-Cut is

the problem

Split the vertices of a graph into two groups. Here, think of it as painting each vertex "colour 0" or "colour 1". An edge whose two ends have different colours is a cut edge. Max-Cut asks for the colouring with the largest number of cut edges. There is also a version with edge weights. This project only deals with the unweighted one.

As a formula: with sv ∈ {0, 1} the colour of vertex v, find the s that maximizes

C(s) = Σ(u,v) ∈ E [ su ≠ sv ] ([ ] is 1 if the condition holds, 0 otherwise)

A graph with n vertices has 2n colourings (2n−1 really, since swapping all colours gives the same cut). For n = 1024, as used in this project, that is 21023 ≈ 10308, far too many to try.

The hardness is also known in theory. The decision version of Max-Cut is one of Karp's 21 NP-complete problems (1972). Even approximating it is hard: unless P = NP, no algorithm can guarantee more than 16/17 ≈ 0.941 of the optimum (Håstad 2001).

Link to the Ising model

Replace the colours by σv = ±1 (+1 for colour 0, −1 for colour 1). An edge (u, v) is cut exactly when σuσv = −1. So C = Σ (1 − σuσv) / 2, and maximizing the cut is the same as minimizing Σ σuσv. That is the energy of an antiferromagnetic Ising model, a model of magnets that prefer to point opposite to their neighbours. This is why Max-Cut is the standard benchmark for quantum annealers and Ising machines.

It also has applications. Assigning the wires of a circuit board or a chip to two layers so as to minimize the holes between layers (vias) is a Max-Cut problem. So is finding the lowest-energy state of a spin glass in statistical physics.

02Ways to solve it

exact, approximate, heuristic, special hardware

Methods fall into four groups, by what they guarantee.

ApproachTypical methodsWhat you get
Solve exactlyBranch and bound with semidefinite-programming (SDP) bounds, e.g. BiqMacThe optimum and a proof. Size is limited: random graphs get hard even at a few hundred vertices
Approximate with a guaranteeRandom colouring (half the edges in expectation). Goemans–Williamson (1995): solve an SDP, then round randomlyAt least a fixed fraction of the optimum. Goemans–Williamson gives about 0.878, which is the best possible if the Unique Games Conjecture holds
Find good solutions fast (heuristics)Local search, simulated annealing, tabu search (e.g. Breakout Local Search), rank-two relaxation (Burer–Monteiro–Zhang), replica exchangeNo guarantee, but in practice optimal or near-optimal cuts, fast. The best-known values on the G-set benchmark have been improved by methods of this kind
Special-purpose machinesQuantum annealers (D-Wave), coherent Ising machines, Digital Annealer, simulated bifurcation machine (runs on FPGAs and GPUs)Search the problem in Ising form with dedicated, parallel hardware

This project is in the third group: it does not prove optimality, it aims for good cuts found fast. Within that group it uses simulated annealing, for three reasons: the procedure is simple, it can be written with integers only, and many independent searches are easy to run side by side. All three make it a good fit for a circuit, so this is also a small, hand-built experiment with the fourth group, special-purpose hardware.

03Simulated annealing

as used here

Flip one vertex at a time

The simplest method is local search: pick a vertex, and flip its colour if that increases the cut. Repeat until no flip helps. The change ΔC from flipping vertex v depends only on v's neighbours. Let nsame be the number of neighbours with v's colour and nopp the number with the other colour. Flipping v turns every edge to a same-colour neighbour into a cut edge, and every edge to an opposite-colour neighbour into an uncut one:

ΔC = n_same − n_opp = 2·n_same − d (d is v's degree, the number of neighbours)

Sometimes accept a flip that makes things worse

Local search stops at a state where no single flip helps (a local optimum). Simulated annealing (Kirkpatrick et al., 1983) gets past this by also accepting a flip that lowers the cut, with probability eΔC/T (the Metropolis rule). T is the "temperature". It starts high, so many such flips are accepted, and is lowered step by step until almost none are. The name comes from annealing metal: cooling it slowly so its crystals settle.

If every vertex has the same degree d, ΔC takes only d + 1 values. For d = 4, used in this project:

Choices made in this project

  • Visit the vertices in order, 0, 1, …, n−1 (one pass is a sweep). This reached the target about 4× sooner than picking a random vertex each time (measured). It also suits the circuit, as explained below.
  • Lower the temperature geometrically from 0.8 to 0.2 in 100 steps, 10 sweeps per step, 1000 sweeps in all. The start and end temperatures were chosen with a grid search on the CPU version.
  • Each replica has its own xorshift64 generator (Marsaglia 2003). It is advanced exactly once per trial, and its upper 32 bits are r.
  • No exp is computed. A flip is accepted if ΔC ≥ 0 or r < TH[n_same]. The threshold table TH = ⌊eΔC/T · 232⌋ is computed once per temperature step on the CPU and turned into integers.
Bit-for-bit the same search

Floating point is used only for the moment the threshold table is built. After that everything is integer, so the Mac, the board's ARM and the FPGA circuit follow the same search down to the last bit from the same seeds. That is what allows every word the circuit returns to be checked against the CPU. It also means the number of trials needed to reach a target is the same on every engine, so comparing speed is simply comparing trials per second.

Run many, measure time to target

Hundreds of annealing runs that differ only in their initial colouring and random seed (replicas) run at the same time. They are compared with TTS99, a measure common in the Ising-machine literature. If one run of length τ reaches the target cut with probability p, the time to reach it at least once with 99% probability is τ · ln(0.01) / ln(1 − p).

On a random 4-regular graph with n = 1024 (2048 edges), about 57% of replicas reached the best-known cut, 1774, in one run of the standard schedule. TTS99 is about 5,500 sweeps, or about 5.7 million trials per replica (measured). Whether 1774 is optimal is not known.

04How it was built on the FPGA

PYNQ-Z1 · Zynq XC7Z020 · 125 MHz

The PYNQ-Z1 carries a Zynq XC7Z020: two ARM Cortex-A9 cores and an FPGA on one chip. The FPGA part has 53,200 LUTs (small logic blocks), 106,400 flip-flops and 140 block RAMs of 36 Kb. The annealing circuit is written by hand in Verilog and runs at 125 MHz.

One trial reads the colours of vertex v and its 4 neighbours, counts nsame, advances the random number and compares it with a threshold, then writes the colour and the cut value if the flip is accepted. Built naively, reading memory in 5 places per trial is the problem: a block RAM has only two ports. Three ideas solve it.

Idea 1: interleave 16 replicas in one pipeline

A trial is split into a 5-stage pipeline, and the trials of replicas 0, 1, 2, …, 15 enter it one per clock in turn. The pipeline accepts one trial every clock, so one pipeline (a lane) does 125 million trials per second.

Idea 2: all replicas work on the same vertex, and colours are stored as one word per vertex

Since vertices are visited in order, all replicas work on the same vertex v for 16 clocks. Call those 16 clocks a window. During a window the colours of v's neighbours do not change: only v changes, and v is not its own neighbour.

So the colouring is kept in BRAM as one word per vertex holding that vertex's colour in every replica. Bit p is the colour in replica p. Four word reads at the start of a window then give the neighbours' colours for all replicas. That is a few reads per 16 clocks, and adding lanes only makes the word wider, so a single BRAM port is enough.

Idea 3: per-replica state in LUT memory, exp replaced by a table lookup

Each replica's random state (64 bits), cut value, best value and the trial at which the best was found live in LUTRAM, LUTs used as small memories. The acceptance test needs only two 32-bit comparators (for nsame = 0 and 1) and a little logic.

How it was checked

  • Simulation: four jobs back to back, with random gaps in the input and back-pressure on the output. Every returned word (each replica's best value, its trial number, the final colouring and so on) matches the CPU version, for 1, 2, 4, 8, 48 and 56 lanes.
  • Breaking it on purpose: disabling forwarding, delaying the write-back by one clock, or capturing the prefetched words one clock early all produce mismatches, as they should. This confirms the test does not miss real errors.
  • On the board: the CPU version on the board generates the expected values, and every word from the circuit is compared with them. All match for 1, 2, 4, 8, 16, 32, 48 and 56 lanes.

What ran out first

At 48 lanes, timing failed first. The cause was not the annealing logic but routing congestion in the control signals for loading, which fan out to every lane. Registering those signals once inside each lane fixed it. At 64 lanes the placer ran out of slices, the space the circuit is placed in. At that point one lane used about 600 LUTs, roughly 40% of them LUTRAM holding per-replica state.

So the LUTRAM was trimmed: trial numbers went from 48 to 32 bits, and results are now read through the write port, which removes a separate read port. A lane came down to about 450 LUTs and 56 lanes (896 replicas) fit. Raising the clock to 142.86 MHz fell short by 0.1 to 0.4 ns. The last worst path was inside the AXI DMA.

05Result: the M4 is faster

same algorithm, same results, different speed

The comparison is against a version of the same algorithm made as fast as possible for CPUs (sa_fast.c). It gives bit-identical results to the circuit. Trials per second are compared on the n = 1024 4-regular graph with the standard schedule.

63× faster than the CPU on the same board, 4.3× slower than a current one.

The M4 is faster because of bit-slicing. The random states of 128 replicas are transposed into 64 words of 128 bits, where word b holds bit b of every replica's 64-bit state. Then the shifts and XORs of xorshift64 become XORs between whole words, and one instruction advances the generators of 128 replicas. The acceptance test r < TH can also be decided on whole words, from the top bit down. The FPGA, in contrast, spends one lane (about 450 LUTs) per trial per clock. This is also a 28 nm FPGA from 2012 against a 3 nm CPU from 2024. Matching the M4 at 125 MHz would take about 240 lanes (estimate).

Comparing time to target (TTS99)

Time to target was also compared on the toroidal graphs of the G-set benchmark (3000 vertices, 6000 edges, degree 4). G48 and G49 are bipartite, so cutting all 6000 edges is optimal. For G50, the best-known value 5880 was reached by just 1 of 1,024 replicas in a long run of 100,000 sweeps. On hard targets the ratios follow throughput. On easy ones, every engine reaches the target with more than 99% probability in one short run of 100 sweeps, so the length of a single run decides it. One FPGA sweep takes (number of vertices) × 16 clocks no matter how many lanes there are (more lanes only add replicas), and the gap to the M4 shrinks to about 2×.

Adding replica exchange to the circuit

As a next step beyond annealing, replica exchange (parallel tempering) was added to the circuit. The 16 replicas of a lane each run at a different temperature (16 steps from 0.35 to 1.0), and after every sweep neighbouring temperatures are swapped with a probability that depends on the difference of their cuts. What is swapped is the temperature index, not the colouring, so the circuit only needs a 4-bit index per replica and a threshold table per temperature. A small engine in the circuit makes the swap decisions during the next sweep, and they take effect from the sweep after that. The CPU version follows the same rule, bit for bit.

It helps more the harder the target: on 5876 it is 6.7× faster than annealing on the same FPGA, and it also beats annealing on the M4. That gain comes from the method, though. The CPU version of replica exchange is not optimized yet, and an optimized one on the M4 would most likely win again (estimate). The exchange engine costs resources, so the lanes went from 56 to 48.

Next steps:

  • Energy per trial. The board draws a few watts and the Mac mini a few tens of watts under load, so the comparison may come out differently there (not measured yet).
  • Optimize the CPU version of replica exchange with bit-slicing, and compare replica exchange against replica exchange.
