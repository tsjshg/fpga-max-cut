最大カット問題を FPGA で解く

グラフを 2 色に塗り分けて、色の違う辺をなるべく多くする。問題の言い方は単純ですが、厳密に解くのはとても難しい問題です。 このページでは、最大カット問題とは何か、どんな解き方があるかを整理します。そのうえで、今回選んだ焼きなまし法の要点と、 それを PYNQ-Z1 の FPGA に自作の回路として載せた方法までを説明します。

数字は断りが無いかぎり実測です。実装と測定の記録は GitHub のリポジトリにあります。

  2. どんな解き方があるか

01最大カット問題とは

what Max-Cut is

グラフ（頂点と、頂点どうしを結ぶ辺の集まり）の頂点を、2 つの組に分けます。ここでは「色 0」と「色 1」に塗り分けると考えます。 両端の色が違う辺をカットと呼びます。カットになる辺の本数が最大になる塗り分けを探すのが最大カット問題（Max-Cut）です。 辺に重みが付いた版もありますが、このプロジェクトでは重みの無い版だけを扱います。

式で書くと、頂点 v の色を sv ∈ {0, 1} として、次の値を最大にする s を探します。

C(s) = Σ(u,v) ∈ E [ su ≠ sv ] （[ ] は条件が成り立てば 1、成り立たなければ 0）

n 頂点のグラフには、塗り分けが 2n 通りあります（色を全部入れ替えても同じカットなので、実質は 2n−1 通り）。 このプロジェクトで使う n = 1024 なら 21023 ≈ 10308 通りで、全部を調べることはできません。

難しさも理論的に分かっています。最大カット問題（の判定版）は、Karp が 1972 年に示した 21 の NP 完全問題の一つです。 近似も難しく、最適値の 16/17 ≈ 0.941 倍を超える保証つきの近似は、P = NP でないかぎりできないことが知られています（Håstad 2001）。

イジング模型との関係

色を σv = ±1（色 0 なら +1、色 1 なら −1）に置き換えると、辺 (u, v) がカットのとき σuσv = −1、そうでないとき +1 になります。 したがって C = Σ (1 − σuσv) / 2 で、カットを最大にすることは Σ σuσv を最小にすることと同じです。 これは、隣どうしが逆向きになりたがる磁石の模型（反強磁性イジング模型）のエネルギーを最小にする問題そのものです。 そのため最大カット問題は、量子アニーリング機やイジングマシンの性能比較の定番になっています。

応用もあります。たとえば、プリント基板や LSI の配線を 2 つの層に割り当てて層間の穴（ビア）を減らす問題や、 統計物理でスピングラスの最もエネルギーの低い状態を探す問題が、最大カット問題の形になります。

02どんな解き方があるか

exact, approximate, heuristic, special hardware

解き方は、何を保証するかで大きく 4 つに分けられます。

考え方代表的な方法得られるもの
厳密に解く分枝限定法。上界に半正定値計画（SDP）を使う BiqMac など最適値とその証明。ただし大きさに限りがあり、ランダムなグラフでは数百頂点でも難しくなる
保証つきの近似ランダムに塗る（期待値で辺の半分）。Goemans–Williamson 法（1995、SDP を解いて乱択で丸める）最適値の何倍以上という保証。Goemans–Williamson 法は約 0.878 倍で、ある予想（Unique Games 予想）のもとではこれが最良
速くよい解を探す（ヒューリスティクス）局所探索、焼きなまし法、タブー探索（Breakout Local Search など）、低ランク緩和（Burer–Monteiro–Zhang）、レプリカ交換法保証は無いが、実際には最適かそれに近い解が速く出ることが多い。ベンチマーク集 G-set の最良既知値はこの系統の方法で更新されてきた
専用の計算機量子アニーリング機（D-Wave）、コヒーレントイジングマシン、デジタルアニーラ、シミュレーテッド分岐マシン（FPGA・GPU で動く）イジング模型の形にした問題を、専用の仕組みで並列に探す

このプロジェクトは 3 つ目、最適性の証明は扱わず、よい解を速く得る側です。その中から焼きなまし法を選びました。 理由は 3 つあります。手順が単純であること、整数だけで書けること、独立な探索をたくさん並べやすいことです。 どれも回路にしやすい性質で、4 つ目の「専用の計算機」を手作りで小さく試すことにもなっています。

03焼きなまし法

simulated annealing, as used here

1 頂点ずつ反転する

いちばん素朴な方法は局所探索です。頂点を 1 つ選び、その色を反転するとカットが増えるなら反転する。これを、どの頂点を反転しても増えなくなるまで続けます。 頂点 v を反転したときのカットの増え方 ΔC は、v の隣だけを見れば分かります。 v と同じ色の隣の数を nsame、違う色の隣の数を nopp とすると、反転によって同じ色の隣との辺はカットになり、違う色の隣との辺はカットでなくなります。

ΔC = n_same − n_opp = 2·n_same − d （d は v の次数 = 隣の数）

悪くなる反転も、ときどき受け入れる

局所探索は、どの反転でも良くならない状態（局所最適）で止まってしまいます。焼きなまし法（Kirkpatrick ほか 1983）はここを越えるために、 カットが減る反転も確率 eΔC/T で受け入れます（Metropolis 法）。T は「温度」で、初めは高くしてよく受け入れ、だんだん下げて最後はほとんど受け入れないようにします。 金属をゆっくり冷やして結晶を整える「焼きなまし」になぞらえた名前です。

次数 d が全頂点で同じなら、ΔC は d + 1 通りしかありません。このプロジェクトで使う d = 4 では次のとおりです。

このプロジェクトでの決めごと

  • 頂点は 0, 1, …, n−1 の順に回す（1 巡りを 1 周回と呼ぶ）。毎回ランダムに選ぶより、目標に届くまでの時間が約 4 倍短くなりました（実測）。回路にとっても都合がよいのは後で説明します。
  • 温度は 0.8 から 0.2 まで幾何級数で 100 段、各段 10 周回、合わせて 1000 周回。初めと終わりの温度は、CPU 版で格子状に試して決めました。
  • 乱数はレプリカごとの xorshift64（Marsaglia 2003）。1 試行に必ず 1 回進め、上位 32 bit を r とします。
  • exp は計算しない。受け入れの判定は「ΔC ≥ 0、または r < TH[n_same]」だけにします。 しきい値の表 TH = ⌊eΔC/T · 232⌋ は、温度の段ごとに CPU が 1 回だけ計算して整数にします。
ビット単位で同じ探索

浮動小数を使うのは、しきい値の表を作る一瞬だけです。そのあとは整数だけなので、 Mac・ボードの ARM・FPGA の回路が、同じ種から最後のビットまで同じ探索をします。 そのおかげで、回路の出力を CPU 版と全語で照合できます。また、目標に届くまでの試行回数はどこで走らせても同じなので、 速さの比較は「1 秒に何回試行できるか」の比較になります。

たくさん並べて、到達時間で測る

初期の塗り分けと乱数の種だけが違う焼きなまし（レプリカ）を、何百本も同時に走らせます。 評価には、イジングマシンの分野でよく使う TTS99 を使います。長さ τ の焼きなまし 1 回で目標のカット値に届く割合が p なら、 99% の確率で一度は届くまでの時間は τ · ln(0.01) / ln(1 − p) です。

n = 1024 のランダム 4 正則グラフ（辺 2048 本）では、標準のスケジュール 1 回で、最良既知値 1774 に届くレプリカが約 57% ありました。 TTS99 は約 5,500 周回、1 レプリカあたり約 570 万試行です（実測）。1774 が最適かどうかは分かっていません。

04FPGA でどう作ったか

PYNQ-Z1 · Zynq XC7Z020 · 125 MHz

PYNQ-Z1 は、ARM Cortex-A9 が 2 つと FPGA が 1 つのチップ（Zynq XC7Z020）に載ったボードです。 FPGA の部分は、LUT（小さな論理回路）53,200 個、フリップフロップ 106,400 個、ブロック RAM（36 Kb）140 個でできています。 焼きなましの回路はすべて Verilog で手書きし、125 MHz で動かしました。

1 回の試行でやることは、頂点 v と隣 4 つの色を読む、nsame を数える、乱数を進めてしきい値と比べる、受け入れなら色とカット値を書く、です。 素直に作ると、1 試行ごとにメモリを 5 か所読むのが窮屈になります。ブロック RAM には、1 つにつき読み書きの口が 2 つしかありません。 これを 3 つの工夫で解きました。

工夫 1：16 レプリカを 1 本のパイプラインに交互に流す

試行の処理を 5 段のパイプラインにし、レプリカ 0, 1, 2, …, 15 の試行を 1 クロックずつ交互に入れます。 パイプラインは毎クロック 1 試行を受け付けるので、1 本（レーン）で 1 秒に 1.25 億試行です。

工夫 2：全レプリカが同じ頂点を処理し、色を頂点ごとの語で持つ

頂点は順に回すと決めたので、16 クロックの間、全レプリカが同じ頂点 v を処理します。この 16 クロックを窓と呼びます。 窓の間、v の隣の色は変わりません（変わるのは v だけで、自分自身とはつながっていないため）。

そこで塗り分けを、頂点ごとに「全レプリカぶんの色を並べた語」として BRAM に持ちます。ビット p がレプリカ p の色です。 すると、隣の色は窓の始めに語を 4 つ読むだけで全レプリカぶんがそろいます。読み出しは 16 クロックに数回で、 レーンを何本に増やしても語の幅が広がるだけなので、BRAM の口 1 つで足ります。

工夫 3：レプリカごとの状態は LUT のメモリに、exp は表の比較に

乱数の状態（64 bit）、カット値、最良値と、それが出た試行番号は、レプリカごとに LUT を小さなメモリとして使う LUTRAM に置きます。 受け入れの判定は、32 bit の比較器 2 つ（nsame = 0 と 1 の場合）と、小さな論理だけで済みます。

確かめ方

  • シミュレーション：ジョブを 4 つ続けて流し、入力にランダムな途切れを、出力に背圧をかけます。返ってくる全語（各レプリカの最良値・試行番号・最後の塗り分けなど）が CPU 版と一致することを、レーン数 1・2・4・8・48・56 で確かめました。
  • わざと壊す：フォワーディングを切る、書き戻しを 1 クロック遅らせる、先読みの受け取りを 1 クロック早める。この 3 つは、ちゃんと不一致になります。試験が誤りを見逃していないことの確認です。
  • 実機：ボード上で CPU 版が期待値を作り、回路の出力の全語と照合します。レーン数 1・2・4・8・16・32・48・56 のすべてで一致しました。

詰まった順番

48 レーンで最初にタイミングが通らなくなりました。原因は焼きなましの演算ではなく、読み込み用の制御信号を全レーンに配る配線の混雑です。 その信号を各レーンで 1 段レジスタに受けると通りました。64 レーンでは、回路を置く場所（Slice）そのものが足りなくなりました。 このとき 1 レーンは LUT を約 600 個使い、その 4 割ほどがレプリカごとの状態を持つ LUTRAM でした。

そこで LUTRAM を詰めました。試行番号を 48 bit から 32 bit にし、結果は書き込みの口から読むようにして、読み出し専用の口をなくしました。 1 レーンは約 450 LUT になり、56 レーン（896 レプリカ）が入りました。クロックを 142.86 MHz に上げる試みは、あと 0.1〜0.4 ns 届きませんでした。 最後の最悪経路は AXI DMA の中です。

05結果：速さでは M4 に負ける

same algorithm, same results, different speed

比べる相手は、同じアルゴリズムを CPU 向けにできるだけ速くした版（sa_fast.c）です。結果は回路とビット単位で同じです。 n = 1024 の 4 正則グラフ、標準のスケジュールで、1 秒あたりの試行回数を比べます。

同じボードの CPU には 63 倍勝ち、最新の CPU には 4.3 倍負ける。

M4 が速い理由はビットスライスです。128 レプリカの乱数の状態を並べ替えて、「64 bit の状態のビット b を、128 レプリカぶん集めた 128 bit の語」を 64 本持ちます。 すると xorshift64 のシフトと XOR は、語どうしの XOR になります。1 命令で 128 レプリカぶんの乱数が進むわけです。 受け入れの比較（r < TH）も、語のまま上の桁から順に決められます。 一方の FPGA は、1 レーン（LUT 約 450 個）で 1 クロックに 1 試行です。2012 年の 28 nm の小さな FPGA と、2024 年の 3 nm の CPU の比較でもあります。 125 MHz のまま M4 に並ぶには、約 240 レーンが要る計算です（試算）。

到達時間（TTS99）で比べる

G-set のトーラス状のグラフ（3000 頂点・6000 辺・次数 4）でも、目標に届くまでの時間を比べました。 G48 と G49 は二部グラフなので、6000 本すべてを切れるのが最適です。G50 の最良既知値 5880 は、10 万周回の長い実行で 1,024 レプリカ中 1 つだけ届きました。 機械ごとに最も速くなる実行の長さ τ を選んだ TTS99 は次のとおりです（実測、詳しい表）。

難しい目標では、比はほぼ試行/秒の比のとおりです。易しい目標では、どの機械も 100 周回の短い 1 回で 99% 以上の確率で届くので、1 回の実行の短さで決まります。 FPGA の 1 回は 1 周回 = 頂点数 × 16 クロックで、レーンを増やしても縮まず（レプリカが増えるだけ）、M4 との差は約 2 倍に縮みます。

これからは次のことを確かめます。

  • 電力あたりの比較。ボードは数 W、Mac mini は負荷時に数十 W です。電力あたりでは結果が変わるかもしれません（まだ測っていません）。
  • レプリカ交換法。しきい値の表の割り当てを入れ替えるだけで足せます。
